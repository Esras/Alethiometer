# What is built

Moved out of HANDOFF.md (2026-10-21), unchanged. Per-area detail is in the other files in this folder; this is the feature-by-feature record, and it may be out of date.


- All five views (Incoming, Priorities, Topics, Notes, Reflect) matching the mocks, on SQLite with sample data (`demo_data: true`) or real data (`demo_data: false`).
- Sync framework (`sync/mod.rs`), outbox writeback (`outbox.rs`), connectors: Google Calendar, Slack (Socket Mode + polling catch-up), Microsoft Teams (Graph, polling; chats, channels with admin approval), Jira, GitHub, Obsidian, Proton ICS (busy only). What chat sources share: `docs/chat.md`; OAuth sign-ins share `sync/connectors/oauth.rs`. Setup per source in `app/docs/sources/`.
- **GitHub: live and verified** on a real account (`gh` CLI token, read-only). `team_review_requests: false` (new) drops PRs where you were only pulled in via a team's review request, not a real mention/assignment/comment/authorship — GitHub's `review-requested:@me` search matches team membership, there's no way to exclude it in the query itself; distinguished via the PR detail endpoint's `requested_reviewers` vs `requested_teams`.
- **Work AI: live and verified** on Bedrock Converse (`ai/`) — real `ai.ask` round-trip confirmed against real GitHub data. Small `us.openai.gpt-6-luna` (effort low), large `us.anthropic.claude-opus-5-5`; US regions and `us.` ids only. Ask pane, topic suggestions after every sync (not just ones with new items), AI split of mixed signals.
- **Credentials: a Bedrock API key (bearer token) is the primary path**, not classic IAM access-key/secret — `AwsCreds::Bearer` alongside `AwsCreds::Keys` in `ai/creds.rs`; checks `AWS_BEARER_TOKEN_BEDROCK`/secret `bedrock_api_key` before the IAM-key chain. See `docs/ai.md` §2.
- **Topics can now be created two ways**: manually (`topics.create`, wired into `TopicPicker.svelte`'s "Create '…'" when nothing matches, `t` in Incoming), or **proposed by the small model itself** during triage (`new_topic` in the suggestion reply shape: 2 to 5 words, broad, validated server-side, dedup'd case-insensitively against existing topics) — still lands as `suggested`, never auto-confirmed. Splits: AI triage splits multi-topic signals (new-topic proposals not supported in that shape yet, see `ISSUES.md`); manual split in Unsorted (select messages, `t`).
- **Google Calendar: live.** OAuth client lives in an existing Internal tooling GCP project (not a personal one). First sync arrives read except invites still awaiting your answer. Recurring series: Incoming shows one row per series (next upcoming unseen instance; `sync::collapse_series`), confirm/move files every instance (`incoming::confirm_series`), new instances inherit the series' links and stay quiet (`sync::inherit_series`); topic timeline shows past instances plus only the next future one. Instances past `days_ahead` are dropped (incremental `syncToken` syncs return every instance of an edited series unbounded — had filled the DB to 2051). SyncStatus Connect waits for consent, then syncs.
- **Jira: live** (`qventus.atlassian.net`, classic API token in `jira_api_token`). JQL = yours (assignee/reporter/watcher) OR created in DEVOPS/IT/ITP2 in the last 7 days; Notes → Jira creates in DEVOPS.
- **Incoming**: dismiss (`d`/`u`, 13a; flips `seen`, no column; optimistic; nothing written remotely except Gmail, where it archives and `u` restores), Gmail-only trash (`#`). **Updates on filed items**: unseen items with a `confirmed` link show under their topic with **Seen** instead of Confirm. Views reload when any source's `last_sync_at` changes (SyncStatus's 30 s poll); `suggest_after_sync` re-stamps it so AI suggestions show once the run finishes. Topics that get their first new signal join at the end (above Unsorted). Titles wrap when expanded, tooltips when truncated.
- **Ignore suggestions (2026-10-17; `queries/ignore.rs`, migration 0038):** every dismiss, Gmail trash, confirm and move is recorded in `triage_events` with what it was about (`triage_keys`: Gmail `from`/`domain`/`list`, Slack/Teams `channel`, GitHub `repo`, Jira `project`); `u` deletes the row. After a dismiss or trash, a line under the hatched row suggests the broadest key that passes `ignore_suggestions` (Settings › General: at least 5 actions, 80% dismissed, 60 days), with **Copy filter** (Gmail `from:(…)`/`list:(…)`), **Add to muted** (Slack/Teams, `settings.mute`), or **Open repo/project**, and **Not now** (30 days, `ignore_declines`). New item fields it reads: Gmail `raw_json.from`, `.list`, `.direct`; Slack `.conv`, `.name`; Teams `.name`. Items synced before have no Gmail keys (Slack falls back to titles) until they next change.
- **Gmail: live, reworked.** Incoming mirrors the whole Inbox (read or not), one item per thread with every message; a thread is never split. A new message (yours too) brings a thread back, even when filed; a thread leaving the Inbox in Gmail leaves Incoming. Confirm/Move queue `gmail.file` (category label from `config.category_labels`, must exist in Gmail; marks read unless newer unread mail arrived), the same call archives the thread (todo or not; skipped when newer unread mail arrived), Dismiss `gmail.archive`, `#` `gmail.trash`, `u` `gmail.restore`; moving a filed thread to a topic in another category relabels it (`gmail.relabel`). Senders behind relays (Google Groups, Drive shares, GitHub) are resolved from headers; Jira and Docs comments fall back to address + name. The user's Gmail data was reset (backup in `<data dir>/backup/`) and resynced on this model; a refetch of all 736 Inbox threads was queued to pick up the header-based senders. Shares the calendar's OAuth client, own `gmail.refresh_token`, scope `gmail.modify`. See `docs/sources/gmail.md`.
- **AI token usage**: every answered Bedrock call is recorded in `ai_usage`; the sync status popover shows today / 7-day calls, tokens and cost (prices per model in `ai.prices`, USD per million). `docs/ai.md` "Token usage".
- **Sync status** shows **Syncing…** per source for background syncs too (`sync.status` reports running sources).
- Window opens at 1760×1175.
- **Topics index (12c)** built: filter (`/`; no auto-focus — user uses j/k), Active/Archived, archive (`a`), quiet section (`quiet_days`), next-meeting pills (own thresholds; the strip countdown keeps its 15/5/2 — user: different information), category chips + `c` picker (type-to-filter), New topic (`n`, inline name field), assistant pane scoped to all topics (`ai.ask` scope `topics`). Scroll/selection/filter survive opening a topic.
- **Categories**: `settings.json` `categories` (array, UI order) is the source of truth; the `categories` table mirrors it at startup and every change in Topics index → Categories writes the file back (`queries::categories::save`, temp file + rename). The old map form is migrated once (DB wins). `work`/`life` built in; delete refused while in use. The classification model suggests a category for new topics.
- **Markdown**: `lib/ui/Markdown.svelte`, a small element-building renderer (no `{@html}`) for AI answers and Incoming message text. The ask prompt allows light Markdown.
- `ui_scale` in settings.json: native webview zoom (`set_zoom`), read at startup; user runs 1.15.
- **People, first pass** (17a/17b, 16c; `app/docs/people.md`): a person is a `People/<Name>.md` note (accounts in frontmatter: `slack`, `email`, `jira`, `github`, optional `color`); `queries/people.rs` mirrors the notes into `people`/`person_accounts` and matches every message and item author at read time. Names everywhere in Incoming are in person colours (palette checked against the 16c mock); unknown senders are dotted-underlined and link to a person on click (17b picker, writes the note through the outbox), the item's author in a row's meta line too (`Signal.author`); a sender in 3+ signals in 7 days gets the New person strip (`p`/`l`/Not now). A topic's People panel lists who wrote in its confirmed signals, coloured; the assistant's topic context gets their note gist, backlinks and other topics. Gmail/Jira/GitHub messages now store `author_id`. Sample data has People notes for everyone but Marco (so the strip shows) and two AI-split Slack signals mirroring 15g/15h.
- **Reclassify and merge** (`app/docs/reclassify-and-merge.md`): a topic's chronology is keyboard-driven (18c: j/k, ↵ expand, `t` move, `s` split, "moved to X · u undo"); a Search tab (18d, ⌘↵ in ⌘K) with snippets, topic per result and the same keys; `m` merges topics (index or topic detail), staged until you leave the screen. Pickers open in one fixed dock per view.
- **Slack split review (15g/15h)**: `split` pill and `⋯` gaps on split signals; `s` (only; user's call, ↵ keeps expanding) opens the review in place, on any Slack signal with 2+ messages, split or not (By topic / In order, `t` move, `d` dismiss, `u` undo, `c` confirm groups (↵ does nothing there, so it's never destructive), shift+j/k range select like text, also in Unsorted's message mode). Backend: `incoming.family`, `review_move`, `review_dismiss`, `review_confirm`; `split::move_messages`, `split::prune`.
- **Settings modal (2026-10-02; 26a, 27a, 26c, 25d; `app/docs/settings.md`)**: cog or ⌘,; ⌘⇧, opens the file. Six sections (General, Categories, People, Sources, AI, Developer), sources as sidebar sub-items, find, full keyboard. Every change writes `settings.json` and applies live: settings sit behind a lock (`App::settings()` returns an `Arc`), each source's loops carry a generation so only a changed connector restarts, `ui_scale` zooms in place, the vault path and `fake_now` restart the app (`state::Hooks`). Hand edits come in through a watcher; an invalid file is refused with the error in the Settings header. Rows are generated from `schemars` schemas of `Settings` and of a typed config struct per connector (`settings/sources.rs`; connectors still parse their own JSON, a test keeps defaults in step). `life_calendars` folds into the protoncal source. Secrets stay in `secrets.json` (user's call), write-only from the UI, with set times in `secrets.meta.json`.
- **Type settings**: `ui_font`, `mono_font` (installed fonts via `fontdb`), `ui_font_size`, `reading_font_size`. All hard-coded px font sizes are rem now; reading text (messages, notes, drafts, answers) uses `--fs-read`.
- **Local embeddings** (`embed/`): bge-small-en-v1.5 ONNX run with tract (pure Rust; ONNX Runtime's binaries were unreachable from the cloud build, and tract ships nothing native), downloaded from Hugging Face on first run, vectors in sqlite-vec. Untested with the real model (see ISSUES.md).
- **Glean, search-only (`glean/`, `app/docs/sources/glean.md`)**: hydrated search merges Glean with local FTS (same URL → one row), anchored local check (shared entity + similarity, pins, rejects, window), ⌘K per hi-fi 3b/3c (⌥↵ asks Glean, ⌥A anchor, ⇧↵ off-topic, ⌘T link, ⌘⌫ reject, facet bar), the Search view (18d) with Glean rows, and the Assistant with Glean (3a Sources panel, 3d owner list): small model writes queries, large model cites kept evidence. Built against Glean's published OpenAPI shapes and recorded fixtures; never run against a real instance.
- **Database layer (2026-10-03; `app/docs/db-plan.md` lists what's left; the full plan and how it was built: `git show 03a3899:app/docs/db-plan.md`):**
  - Times are UTC instants or local days (`time.rs`, `clock.rs`; only `Clock` converts).
  - All SQL is in `store/`, behind ports in `domain/`, and a test enforces it.
  - A command runs in one read snapshot or one unit of work, opened by `api.rs`. Commands with network or file IO open short ones around it.
  - Readers are a pool and don't wait for the writer.
  - `app.db()` exists only in tests.
  - New code: add a port method in `domain/<area>.rs`, its SQL in `store/<area>.rs`, and a `route` in the module.
  - Each source has one sync worker (`sync/worker.rs`). Slack polls by stream (`sync_streams`). Items carry the source's revision (`remote_rev`), and messages upsert by key.
  - Triage sends back the `rev` and message keys it showed, and applies only to those. Outbox sends are leased and ordered per item.
  - Derived values (topic counts, latest signal, corpus revision, embedding queue) are kept by views and triggers, checked by `maintained_values_match_their_from_scratch_queries`.
  - Live queries: a view calls `live(cmd, args, onResult)` from `lib/live.ts`, and the core re-runs it when a commit touches a table it read. Every view uses that now but the sync chip; don't add new `ui.rev` readers. A command that also reads vault notes is routed `Route::ReadFiles` and re-runs when the vault changes too.
  - Incoming's list carries message keys and counts; an expanded row loads its messages (`incoming.messages`).
- **OpenShell sandboxes (2026-10-08; `app/docs/agents.md` › OpenShell sandboxes)**: Where › OpenShell in the New agent modal (shown when the `openshell` CLI is on the PATH): gateway, new or existing sandbox, image. A new sandbox is created with the directory uploaded; the adapter runs in it through `openshell sandbox exec` in the agent host, so it's a local ACP session in every other way. Claude Code in `auto` mode; other agents' permission gates allowed automatically, their questions still to you (a pi prompt is a gate only while a tool call is pending). OpenShell's drafted network rules are approvals (Approve rule / Reject). **Bring back** copies the agent's changes into the directory it was uploaded from (three-way against a record of the upload; conflicts left alone unless the sandbox should win). Archiving deletes a sandbox Alethiometer made (outbox, `openshell.delete_sandbox`), Not done while changes haven't been brought back. `agents/openshell.rs`, `agents/openshell/sync.rs`, `sync/connectors/agents.rs`, `agents.openshell` and `agents.harnesses[].openshell` in settings.json, `scripts/fake-openshell.mjs`, `tests/agents_openshell.rs`. Not run against a real gateway much: tried by hand, lightly; what to check is in ISSUES.md.
- **Archiving agents (2026-10-05; Agents Archive 01–05; `app/docs/agents.md` › Archive)**: `a` / right-click on a session, room or group; confirm with the tree as it will change; 10 s undo; local sessions stopped and kept, Scion threads copied locally then their agents deleted through the outbox (`scion.delete_agent`); archived items only through the tree filter, read-only. Table `agent_archive` (migration 0033). Not checked on screen yet: Playwright isn't in the Mac devshell.
- `app.open_url` command (backend `platform::Platform::open_url`, `open`/`xdg-open`) wired to `openExternal()` — "open in GitHub"/"open in Obsidian" links actually open something now; `window.open()` is a silent no-op in Tauri's WKWebView without a plugin this app doesn't have.

- **Agents tab (2026-10-03; Agents Final 01–08; `app/docs/agents.md`)**: tab 7, `g a`. Rust `agents/`: in-memory store the UI polls (`agents.poll`), local state flushed to SQLite (`0017_agents.sql`). Local ACP client (hand-written, std threads) launching `claude-agent-acp` / `pi-acp` per `agents.harnesses`; agents run in the **agent host** (`app/agentd`, a separate small daemon on a Unix socket in the data dir, run from a copy in `<data dir>/bin/`), so a quit, crash or dev rebuild of the app leaves them running, approvals included; the app reattaches from the host's numbered event log and the stored turn state (`agent_hosts`). Quit no longer stops agents (Stop / Stop all do). An exited agent is resumed when messaged (`session/resume`, else `session/load`). Approvals use the agent's own options; `agents.accept_edits` starts sessions in the agent's accept-edits mode. Parsed panel = `tree-sitter-bash` + our command table (`agents/shell.rs`, corpus test from godspede/construct-auto-classifier); Explained = small tier. Scion Hub client (`agents/scion*`, a `scion` source) built from the Go source, polling. Facts box (git, Jira, GitHub, todos), Unsorted group guess (small tier), Settings › Agents (section 6, live preview). Dev stand-ins: `scripts/fake-acp.mjs`, `scripts/fake-scion-hub.mjs`.

- **Answering from Alethiometer (2026-10-07; `queries/respond.rs`)**: RSVP in Incoming (14a) and in a topic's Upcoming and Chronology (14b), and Slack replies from Incoming. Both go through the outbox (`respond.rsvp` → `gcal.rsvp`, `respond.slack` → `slack.reply`) and never triage. A row shows its latest answer from the outbox row: sending, failed (Retry; answering again replaces the failed row, which would otherwise hold back the item's later writes), or done ("Accepted · 10:58", "Change in Google Calendar"; "Replied · 10:58"). Overlaps come from the day strip's blocks, Life as "Life". Decline with note sends the attendee `comment`. `slack.reply` posts to the conversation when it has no `thread_ts`. Sample data: an unanswered "Acme postmortem review" invite in Incoming (overlaps DD prep and a Life block) and an unanswered "Final terms call" on Datadog renewal (overlaps Staff sync). Not run against real Google or Slack yet (ISSUES.md).
