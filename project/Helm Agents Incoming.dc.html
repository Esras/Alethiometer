Alethiometer · Agents in Incoming

How agents show up in Incoming: blocked on you, a message or a turn’s output for you, and finished. This fills the “Also in Incoming” gap that app/docs/agents.md lists under Not built on claude/funny-faraday-mgdokr. The content comes from Agents Final 01–08, and the behaviour follows that branch.

2Agents in Incoming · a topic, Agents waiting, open states

Agent signals are filed under topics like any other signal. The topic is suggested from the session’s ticket, or else from its group, goal and first task. A signal leaves Incoming once you act on it, here or in Agents; just looking at it doesn’t count. A local session gets one signal per turn. The Incoming badge counts agent signals. There’s no orange anywhere: a blocked agent is one signal among many. A collapsed agent row is one line, like any signal. Its actions touch the signal, never the agent: c confirms the topic, t moves it to another, x sends it back to Unsorted, and d takes it out of Incoming. ↵ opens the row, and while it’s open, number keys pick the agent’s answers in its order.

2aA topic. Agents is one more app group in the topic, after GitHub in the fixed order and oldest first like every group. Each agent row is one line: the agent, why it’s here, then project › group · time, with the same actions as any signal. replay is open (↵), showing the full command with its parse and explanation, then the agent’s answers on 1–3. Deny… (3) asks for an optional reason in place.
