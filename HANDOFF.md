- **Build speed (2026-10-08):** `app/src-tauri/.cargo/config.toml` builds the bundled SQLite with `SQLITE_DEFAULT_MEMSTATUS=0`. Its memory-stats mutex serialized every allocation across parallel test threads (unit tests 140 s → 4.4 s on 32 cores). Don't start reading `sqlite3_status`/`soft_heap_limit` without revisiting this. Dependency debuginfo off (`[profile.dev.package."*"] debug = false`) was measured on the Mac: no change to incremental rebuilds; it would still save ~12 s per clean build and ~1.5 GB. Clean-build critical path is `tract-core` → `tract-onnx` → the lib → its test binary.
  - **`npx tauri dev` rebuild (Linux, mold, one-file edit): 6.8 s** = ~1.1 s cargo fingerprinting, 3.6 s the `alethiometer` lib, 2.0 s the binary (mostly link). GNU ld was 23 s in the same clean env. Measure with `cargo build --timings` after appending a comment to a source file.
  - **Open bug: agents inherit cargo's env from a dev build.** Under `npx tauri dev`/`cargo run`, the app's env has `OUT_DIR`, `CARGO_MANIFEST_DIR`, `CARGO_MANIFEST_PATH`, `CARGO_PKG_*` (and `CARGO_TERM_*`), and agents the app spawns inherit them. ring's build script tracks `OUT_DIR`/`CARGO_MANIFEST_DIR`/`CARGO_PKG_NAME`, so every `cargo build` an agent runs (in any project using ring) reruns it and rebuilds ring → rustls → ureq/tungstenite: ~13 s instead of 6.8 s here. Fix: strip those vars when spawning agents (or at app start), with a test. Not done yet. When benchmarking from inside an agent session, `env -u OUT_DIR -u CARGO_…` first, or numbers are inflated.
  - **Remaining options, best first:** (1) dependency debuginfo off, above (~0.5–1 s per rebuild); (2) splitting the 47k-line lib into workspace crates (store/sync/agents/embed) might save 1–2 s of the lib's 3.6 s, a big refactor, skipped; (3) Cranelift backend and the parallel front end need nightly, which the Nix stable toolchain doesn't give us, skipped. UI-only edits never rebuild Rust (Vite HMR).

## User decisions (don't re-ask)

- **2026-10-21 batch:** action errors in every view are toasts (`lib/toast.svelte.ts`, `lib/ui/Toasts.svelte`) in the top-right notices corner with the Reflect nudge, gone after 8 s (hover holds; same text restarts); load errors and in-form validation stay where they were. Incoming's keys live in a `?` sheet (shared `lib/ui/KeySheet.svelte`, sections least to most specific); the bar keeps j/k, c, t, d, u and `? keys`. `o` on any agent signal dismisses it. Explained sees your last three prompts and the agent's message before the latest (labelled as its wording), and gets 2,000 output tokens (900 cut 17 replies mid-JSON). Slack/Teams threads: see "A thread attaches to its parent message" below. Jira Cloud's posts show the person they were posted for, keeping the bot's id. The New agent modal ignores clicks outside it. Note editors are at line-height 1.45 (WebKit draws the caret the line box's height; a caret at text height would need an editor that draws its own). Ignored chat conversations stay one `muted` list in settings.json, shown in Settings as Channels and DMs by name with Add… from seen conversations; `.` on a Slack or Teams signal opens a menu whose `i` ignores its conversation, future messages only. Pi cache-miss notices: on hold (ISSUES.md).

- **Windows and Teams (2026-10-14):** the app should build and run on Windows, **local agents included** (the agent host gets a Windows transport); OpenShell and Scion attach aren't in scope there. The user tests on Windows by hand; no CI. Windows defaults kept: secrets stay in `secrets.json`, data in Roaming `%APPDATA%`, unsigned MSI/NSIS, "Open in Zed". **Microsoft Teams** is a source like Slack, built in stages so it works with only what the tenant allows: chats first (delegated `Chat.Read`/`Chat.ReadWrite`, which users can often consent to), channels once an admin approves `ChannelMessage.Read.All`.
